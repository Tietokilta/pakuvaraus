# @tietokilta/pakuvaraus-client

Typed `fetch` client for the pakuvaraus public API. The types in `schema.d.ts`
are generated by [openapi-typescript](https://openapi-ts.dev) from
[`../openapi.json`](../openapi.json), which is generated from the Rust handlers
with [utoipa](https://github.com/juhaku/utoipa). Requests go through
[openapi-fetch](https://openapi-ts.dev/openapi-fetch/).

```ts
import { createPakuvarausClient, type CreateReservation } from "@tietokilta/pakuvaraus-client";

const api = createPakuvarausClient({ baseUrl: "https://pakuvaraus.example" });

const { data, error, response } = await api.GET("/reservations");
await api.POST("/reservations", { body: reservation satisfies CreateReservation });
await api.POST("/reservations/cancel/{edit_key}", { params: { path: { edit_key } } });
```

`error` is typed per status: `ErrorResponse` (`{ error: string }`) for 404, 409
and 500, and a plain-text string for 400 and 422 (axum's body rejections).

## Updating

After changing an API handler or type, run in the dev shell (`nix develop`):

```sh
update-api-client
```

It rewrites `openapi.json` and `client/schema.d.ts`. `nix flake check` fails
when either is stale. The running server also serves the spec at
`/openapi.json`.

## Releasing

Every push to `main` that changes `client/` runs
[`publish-client.yml`](../.github/workflows/publish-client.yml). When the
package contents differ from the latest published version, it publishes the
next patch version with trusted publishing. It takes major and minor from
`version` in `package.json`, and ignores the patch there.
For a breaking API change, bump the minor version (or the major after 1.0) in
`package.json`, since `^0.1.0` only accepts new `0.1.x` patches. The npm package's
settings must list that workflow as a trusted publisher that is allowed to run
`npm publish`.
